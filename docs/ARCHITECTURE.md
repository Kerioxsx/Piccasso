# Architecture

## Two apps, one behaviour

DrawStep is implemented twice on purpose: a dependency-free web app (PWA) and a native Rust desktop app. Forcing one codebase into both (for example by embedding the web app in a Rust shell) would leave the Rust side without real responsibilities, so instead the **engine is implemented in both languages** and kept identical by three mechanisms:

1. **Shared declarative data** in `shared/`: difficulty tables, styles, paper presets, step kinds and their overlay layers, all user-facing text templates, glossary, pressure tables and colour names. The web app fetches copies from `web/shared/` (kept in sync by `tools/sync-shared.mjs`, enforced by a test); the Rust core embeds the originals with `include_str!`.
2. **A written algorithm spec** ([ALGORITHMS.md](ALGORITHMS.md)) with integer arithmetic and JavaScript-compatible rounding wherever results are compared.
3. **Conformance vectors** (`shared/test-vectors.json`), generated by the JS engine and replayed by `rust/crates/drawstep-core/tests/vectors.rs`: hashes of every primitive and render, contour point lists, the full analysis JSON and the generated steps.

## Modules

| Concern | Web | Rust |
|---|---|---|
| Image primitives | `js/core/image.js` | `drawstep-core/src/imgproc.rs` |
| Analysis (subject, shapes, contours, values, technique) | `js/core/analysis.js` | `analysis.rs` |
| Step generation | `js/core/steps.js` | `steps.rs` |
| Style renderers | `js/core/render.js` | `render.rs` |
| Motion paths | `js/core/motion.js` | `motion.rs` |
| Perspective geometry, paper detection | `js/core/geometry.js` | `geometry.rs` |
| Drawing comparison | `js/core/compare.js` | `compare.rs` |
| Lock state machine | `js/core/lock.js` | `lock.rs` |
| AR/camera capability evaluation | `js/core/capabilities.js` | `capabilities.rs` |
| Project format + validation | `js/core/project.js` | `project.rs` |
| Storage | `js/core/store.js` (IndexedDB) | `store.rs` (one `.drawstep.json` per project + PNG render cache) |
| Pipeline orchestration | `js/core/pipeline.js` + `js/worker.js` | `pipeline.rs` (+ background thread in the app) |
| Auto-draw strokes | n/a | `strokes.rs` |
| UI | `js/ui/*` (screens, canvas renderer, gestures, wake lock, WebXR, AI) | `drawstep-app/src/*` (egui screens, phone bridge, auto-draw, camera) |

## Data flow

```
source image ──prepare (rotate/flip/crop/resize/adjust)──► analysis image (≤320 px) ──analyze──► Analysis
     │                                                                                          │
     └──prepare (≤1280 px)──► render styles + step bases (light/outline/values/sketch)          ├──► steps (templates + numbers)
                                                                                                └──► motion paths / strokes
```

Processed images are re-derived from `source + prep`, so project files stay portable and small; both apps cache renders locally (IndexedDB / PNG files) keyed by a hash of the prep.

## Responsiveness and cancellation

Web: the pipeline runs in a module Web Worker; cancel terminates the worker instantly. Desktop: a background thread with an `AtomicBool` checked between stages; the UI polls a channel for progress.

## Platform services

- Keep awake: Screen Wake Lock API (re-acquired on visibility change) / `keepawake` crate.
- Camera: `getUserMedia` / nokhwa (feature) / phone bridge.
- AR: WebXR `immersive-ar` with `hit-test` and `anchors` (`js/ui/webxr.js`). Desktop reports AR as unavailable and offers overlay alignment.
- Mouse control: enigo (X11 via x11rb, Windows SendInput, macOS CoreGraphics).
